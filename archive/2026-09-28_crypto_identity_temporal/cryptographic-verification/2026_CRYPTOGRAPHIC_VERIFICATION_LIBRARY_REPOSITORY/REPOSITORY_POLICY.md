# Repository Policy

The preservation layer is immutable in concept: original package names, relative paths, and bytes are not to be changed for presentation. Classification views may duplicate artifacts but must not replace or rename the preserved originals. Any future normalization must be emitted as a derived layer with explicit antecedent hashes.

Formal proof filenames must remain compatible with their original import/module expectations. Ordering belongs in indexes, not filename prefixes.

Failures, compile errors, unavailable-toolchain receipts, hostile cases, and unresolved obligations remain first-class evidence.
