2026-08-15 ML-KEM-768 FORENSIC ADJUDICATION

BOTTOM LINE

The supplied six-vector file is not six corrupt or arbitrary vectors. It is a fully coherent,
deterministic KEM generated by a specific algebra/domain mistake.

The exact implementation defect has been identified and independently reproduced:

  SampleNTT(rho, j, i) produces the standard matrix entries in NTT representation.
  The implementation then treats those NTT-representation coefficient arrays as if they were
  ordinary coefficient-domain ring polynomials.
  It multiplies them by the raw CBD eta=2 secret/error polynomials using ordinary negacyclic
  polynomial convolution, rather than performing the required NTT-domain multiplication.

That exact wrong-domain operation reproduces every supplied public key and ciphertext byte-for-byte.

RESULTS

Six positive vectors:
  6 / 6 raw secrets independently regenerated from d and match the supplied coefficient-domain secret.
  6 / 6 coefficient-domain secrets, after standard ML-KEM NTT, match OpenSSL 3.5.5's canonical
        private PKE secret component for the same deterministic seed.
  6 / 6 rho values match the independent OpenSSL key generation.
  0 / 6 supplied public keys match OpenSSL/FIPS-203 public keys.
  6 / 6 supplied public keys are reproduced exactly by the identified wrong-domain algebra.
  6 / 6 supplied ciphertexts are reproduced exactly by the same wrong-domain algebra.
  6 / 6 supplied shared secrets are reproduced exactly.

Private-key layout:
  The supplied 2400-byte dk is internally structured as:
    1152-byte coefficient-domain secret || ek || H(ek) || z
  The ek/H(ek)/z tail is internally consistent for all six vectors.
  The first 1152 bytes are the raw sampled eta=2 secret. Standard FIPS-style expanded storage
  uses the NTT-domain form there; applying the standard NTT maps the supplied secret to the
  independent OpenSSL canonical secret component exactly.

Hostile suite:
  15 / 15 byte-executable hostile/control cases reproduce the expected verdict class.
  Every byte-executable case that supplies an expected shared secret reproduces it exactly.
  The ten corruption cases reach implicit rejection and reproduce J(z || ct).
  The three malformed ciphertext length cases reject by length.
  wrong_dk reaches implicit rejection.
  control_valid accepts and reproduces the expected shared secret.
  ek_wrong_size_1183 is not byte-executable from this JSON because the malformed ek bytes are
  not present; only the scenario description and expected length-rejection verdict are present.

STANDING

These vectors are valid evidence for the implementation they actually encode, but they are NOT
byte-compatible FIPS-203 ML-KEM-768 KATs.

The strongest accurate description is:

  "Internally coherent ML-KEM-shaped KEM with standard seed sampling, FO-style outer KEM logic,
   standard compression/encoding, but a wrong-domain K-PKE algebra in which NTT-representation
   matrix entries are multiplied as coefficient-domain polynomials."

This distinction must be preserved in release/provenance records. The vectors should not be
silently rewritten. A corrected canonical-FIPS successor vector set should be generated as a
new artifact, while this set remains preserved as evidence of the original implementation.
