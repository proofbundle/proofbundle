# From-scratch crypto core

Keccak-f[1600] / FIPS 202 and ML-KEM / FIPS 203, written from the specifications in
pure JavaScript. No external crypto library, no WebCrypto, no `noble-*`.

```
keccak.mjs        SHA3-256/384/512, SHAKE128/256           FIPS 202
mlkem.mjs         ML-KEM-512/768/1024                      FIPS 203
```

`mlkem.mjs` takes its hashing from `keccak.mjs`, so the two together are a closed
dependency graph rooted only in the language itself.

## Running the tests

Everything resolves by relative path, so run from inside this directory:

```bash
cd crypto
node t_keccak.mjs      # 88 pass  — against node:crypto
node t_mlkem.mjs       # 40 pass  — structural / self-consistency
node t_ref.mjs         # 45 pass  — against an independent implementation
```

Or from the repository root:

```bash
npm run test:crypto
```

## What the tests establish

**`t_keccak.mjs` — 88 checks against `node:crypto`.** Every SHA-3 and SHAKE function
is compared to Node's own implementation across 11 message lengths (including the
rate boundaries where sponge padding is easiest to get wrong) and a 100KB case, plus
11 SHAKE output lengths that cross squeeze boundaries, plus three hardcoded FIPS 202
known-answer values.

**`t_mlkem.mjs` — 40 structural checks.** No reference implementation is consulted.
These are properties a broken implementation cannot satisfy: the NTT is invertible;
NTT-domain multiplication agrees with an independent schoolbook convolution in
`Z_q[X]/(X^256+1)` that shares no code with it; encapsulate and decapsulate agree on
the shared secret across all three parameter sets; a single flipped ciphertext bit
routes to implicit rejection; the same seed yields byte-identical output.

**`t_ref.mjs` — 45 byte-exact checks against `kyber-py`.** Nine vectors from an
independent Python FIPS 203 implementation, five checks each: encapsulation key,
decapsulation key, ciphertext, shared secret, and decapsulation of the reference
ciphertext. This is the check that catches an error consistent across our own
encapsulate and decapsulate paths — the class of bug the structural tests are blind to.

The zeta and gamma tables in `mlkem.mjs` are derived at load time from the primitive
root, not transcribed, so a typo in a constant table cannot silently corrupt the
transform. The same applies to the FIPS 180-4 constants elsewhere in the project.

## Integrity

`MANIFEST.json` carries SHA-256, SHA-512, BLAKE3 and byte counts for every file here.
The two source modules and all three harnesses are byte-identical to that manifest.

`RESULTS.txt` is not tracked: it is regenerated by running the tests, and the manifest
entry for it records an earlier, shorter revision of the summary text than the one the
current harnesses print. The code hashes are the ones that matter and those match.
